完全公平调度器归属于公平的调度器类，在所有调度器类的优先级中，仅高于空闲类:
```text
stop > deadline > rt > fair > idle
```

并且，他是大多数用户态进程的默认策略。如果需要rt等更高优先级的，需要通过专门的系统调用来实现，一般用的比较少，只有一些专用场景，如传感器采集，传感器融合等会使用到。

### CFS调度器原理

##### 核心思想
CFS调度器采用所谓的**虚拟运行时间**(vruntime)来决定每个进程是否获得CPU:
-  每个进程会有一个所谓的nice值权重，这个权重会影响其获得cpu时间的多少
-  权重越高的进程，代表其更加重要，其vruntime会增加得更慢
-  调度器总是会选择vruntime最小的进程来运行。因此，那些权重更高的进程有更大的概率被选中。因此我们说这是一种综合考虑多种因素的相对公平算法，而不是绝对公平

虚拟运行时间(vruntime)的计算公式如下：
$$vruntime=rruntime*1024/weight$$
rruntime指的是实际的运行时间。可以看到，权重越高，vruntime就会上升的越慢，导致该进程更有可能被选中。

前面我们还提到了一个nice值。他其实是和权重一一对应的。nice值的范围是-20到+19, 默认的nice值为0. 下面就给出了nice值所对应的权重：
```c
// include/linux/sched.h
// nice 值范围: -20 到 +19
// 默认 nice 值: 0
// nice 值越小，优先级越高

static const int prio_to_weight[40] = {
    /* -20 */ 88761, 71755, 56483, 46273, 36291,
    /* -15 */ 29154, 23254, 18705, 14949, 11916,
    /* -10 */ 9548,  7620,  6100,  4904,  3906,
    /*  -5 */ 3121,  2501,  1991,  1586,  1277,
    /*   0 */ 1024,  820,   655,   526,   423,
    /*   5 */ 335,   272,   215,   172,   137,
    /*  10 */ 110,   87,    70,    56,    45,
    /*  15 */ 36,    29,    23,    18,    15,
};

// NICE_0_LOAD = 1024 (nice=0 时的权重)
```

可以看到，nice值为0时，就是按照实际运行时间来分配。nice值越高，权重越低，vruntime增加的越快，越不会被调度器选中，对于其他进程而言越"nice". 

这就是CFS的全部核心思想，简单但是实用。


### 依赖的数据结构

CFS底层用**红黑树**来管理所有可运行的进程，得益于红黑树的如下特性：
- O(logn)的查找，插入，删除复杂度
-  树中最左边的节点就是vruntime最小的进程
-  适合频繁的调度操作
