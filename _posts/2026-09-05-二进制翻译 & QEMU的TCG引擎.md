二进制翻译是虚拟化的一种技术路线，一句话概括，就是把**已经编译好的机器码A, 转换成另一段机器码B, 然后执行B, 而不是执行A**。 这里的二进制不是二进制文件，而是机器指令(二进制指令编码)。

在客户机和宿主机同架构下，一般会采用KVM等技术(需要硬件虚拟化支持)来做虚拟化。如果是异架构，那么就只能用二进制翻译技术了。在QEMU下，上述两种方式都得到了支持。QEMU主要有两种运行模式：
-  System Mode： 模拟整个机器(CPU, 内存和虚拟外设)用来支持操作系统的运行
-  User Mode：允许在一个CPU架构上运行另一个CPU架构编译的用户态进程

常见的二进制翻译技术可以概括如下：
-  解释器，即Interpreter, 每次解析并执行一条Guest指令，循环往复。每一条指令都需要翻译一      次，来一个翻译一个，类似同声传译，效率比较低。
-  静态翻译，即Static Binary Translation, SBT. 在程序运行前，就预先执行翻译任务，翻译完后就    相当于直接执行host架构的程序。这个的优点是没有运行时开销，缺点是无法做热点路径的分析  和翻译缓存， 优化的空间是有限的，以及难以处理一些间接跳转的问题。
-  动态翻译，即Dynamic Binary Translation，DBT. 在程序运行时执行翻译。一般按照程序的trace   翻译，即实际执行路径，而不会做全量翻译。由于根据trace翻译，它可以对热点代码进行深度     优化，因此性能较好。

下面，我们来讲解一下QEMU的TCG引擎。QEMU的TCG就属于上面的动态翻译类型。TCG引擎的一个比较完整的流程可以概括为如下的一个流程图：
```text
                 Guest 程序
                    |
                    v
          +-------------------+
          | Guest CPU 指令流   |
          | (x86/ARM/RISC-V) |
          +-------------------+
                    |
                    v
          +-------------------+
          | QEMU TCG 前端      |
          | Guest ISA decoder |
          +-------------------+
                    |
                    v
          +-------------------+
          | TCG IR            |
          | 中间表示          |
          +-------------------+
                    |
                    v
          +-------------------+
          | TCG 优化器         |
          +-------------------+
                    |
                    v
          +-------------------+
          | TCG 后端           |
          | Host ISA backend  |
          +-------------------+
                    |
                    v
          +-------------------+
          | Host machine code |
          | x86/ARM/RISC-V   |
          +-------------------+
                    |
                    v
              CPU 执行
```

简单来说，guest程序会被翻译为guest架构下的指令流。这个指令流通过QEMU TCG前端被翻译成TCG IR中间表示。经过优化器优化表示后，通过host架构实现的TCG后端，把中间表示翻译为host架构的机器码，最后送到CPU执行。

引入中间表示，相比端到端的翻译，多了一层抽象开销，不过这么做相比较性能的牺牲，带来了诸多的好处：
-  扩展性好：某个host如果期待支持新的guest架构，只需要实现source->IR, 后端部分是复用的，大大降低了工程量。
-  易于流程化：可以在各个环节引入优化策略。
