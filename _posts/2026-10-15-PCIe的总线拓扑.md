## 基本概念

**PCIe（Peripheral Component Interconnect Express，外围组件互连高速扩展标准）** 是一种高速、串行、点对点的计算机互连标准，主要用于连接 CPU/内存系统与各类高速外设，例如 GPU、网卡、NVMe SSD 等。与传统 PCI 的共享总线架构不同，PCIe 采用独立链路（Link）进行通信，并通过多条 Lane 聚合提升传输带宽。

在体系结构上，PCIe 采用树形拓扑，以 **Root Complex（根复合体）** 作为主机系统与 PCIe 网络的连接入口，通过 **Root Port（根端口）** 连接下游设备，并可借助 **Switch（交换设备）** 扩展连接，最终到达 **Endpoint（端点设备）**。PCIe 还定义了标准化的 **Configuration Space（配置空间）**，使操作系统能够以统一的方式发现、识别、配置和管理不同厂商的 PCIe 设备。

**PCI/PCIe的核心目的，是为计算机主机系统与外设之间提供一套标准化的互联机制。** 它不仅要解决主机与外设之间的数据传输问题，还需要解决设备发现、设备控制、资源分配以及事件通知等一系列问题，使不同厂商生产的外设能够遵循统一的标准接入计算机系统。

假设我们是一家网卡厂商，正在设计一张网卡。为了使这张网卡能够正常工作，至少需要解决以下几个问题：
1. **设备发现与识别**：操作系统如何知道这张网卡的存在，以及它由哪家厂商生产、具备什么功能？
2. **设备控制**：CPU 如何访问网卡内部的控制寄存器，例如启动网卡、配置收发队列？
3. **数据传输**：网卡如何与主机内存交换数据？能否通过 DMA 主动读写内存，而不需要 CPU 逐字节搬运？
4. **事件通知**：当网卡接收到新的数据包时，如何通过中断通知 CPU？
5. **资源分配与管理**：操作系统如何为网卡分配地址空间、中断等资源，并避免不同设备之间发生冲突？

如果没有统一的互联标准，每家设备厂商都需要自行设计与主机通信的接口，而 CPU、主板和操作系统也必须针对不同设备进行适配，整个硬件和软件生态将难以实现通用性。

PCI/PCIe 正是为了解决这类问题而设计的。它定义了一套统一的设备互联与管理模型，使设备厂商只需遵循相应标准，就能够接入支持 PCI/PCIe 的主机平台。至于设备内部如何实现自身功能，例如网卡如何处理网络数据包、GPU 如何完成图形渲染，则不属于 PCI/PCIe 需要规定的内容。

虽然 PCI/PCIe 提供了完善的设备互联机制，但并不是所有外设都需要使用它。

**外设选择何种接口，本质上取决于通信带宽、访问延迟、功能需求、功耗、硬件成本以及使用场景等因素。**

下面列举几种常见的外设接口：

| 接口   | 典型设备              | 主要特点                      |
| ---- | ----------------- | ------------------------- |
| I²C  | 温度传感器、电源管理芯片      | 引脚少、成本低，适合低速控制通信          |
| SPI  | Flash、传感器、显示控制器   | 协议简单，适合板级短距离通信            |
| UART | 串口控制台、通信模块        | 实现简单，适合低速串行通信             |
| USB  | 鼠标、键盘、摄像头、移动存储    | 通用性强，支持热插拔，适合外部设备         |
| PCIe | GPU、NVMe SSD、高速网卡 | 高带宽、低延迟，支持高效 DMA 和标准化设备管理 |

例如，温度传感器每秒可能只需要传输少量数据，使用简单、低成本的 I²C 接口就可以满足需求。如果为它实现 PCIe 控制器和高速物理接口，不仅增加硬件复杂度，还会带来不必要的功耗与成本。

而 GPU、高速网卡、NVMe SSD 等设备通常需要频繁地与主机交换大量数据，并且希望高效地访问主机内存。对于这类设备，PCIe 所提供的高带宽、低延迟、可扩展互联能力以及成熟的设备管理机制就显得十分重要。

另外，接口的选择并非只由性能决定。例如 USB 同样可以支持高速数据传输，但其便捷的外部连接、热插拔能力和广泛的设备兼容性，使它更适合许多消费级外设。

从系统架构来看，PCI/PCIe 并不是单纯的一条高速数据通道，而是一套**面向计算机 I/O 子系统的标准化互联架构**。

它既规定了主机和外设之间如何进行通信，也建立了相应的设备发现、配置和管理机制。主机可以通过 PCI/PCIe 控制外设，而具有相应能力和权限的外设也能够主动发起事务，例如通过 DMA 访问主机内存。因此，我们可以将 PCI/PCIe 理解为连接主机计算与内存体系和高性能外设的重要桥梁。它的价值不仅在于传输速度，更在于**为不同厂商、不同类型的设备提供了一套统一、可扩展且能够被操作系统管理的互联模型**。

这一节，我们不打算涉及任何关于PCIe的寄存器配置细节，而从系统视角出发，看看整个PCIe系统的接口和层次是什么，都涉及到哪些主体，主体之间的联系是什么，主体自身的职责又是什么。只有在建立了正确的心智模型后，再进入细节学习，方可达到事半功倍的效果。

## 总体架构

下图给出了整个PCIe系统上下游的架构图：
```
                    CPU / Memory
                         |
                   SoC Interconnect
                         |
                         |
                   Root Complex
                         |
                 +-------+-------+
                 |               |
             Root Port       Root Port
                 |               |
            PCIe Switch         GPU
                 |           (Endpoint)
            +----+----+
            |         |
           SSD       网卡
        (Endpoint) (Endpoint)
```

CPU/Memory通过总线互联，访问到了所谓的`Root Complex`. 然后，`Root Complex`下面会导出数个`Root Port`,  Root port之后可以接入一个所谓的`PCIe Switch`, 或者接入`Endpoint`. 并且，我们可以发现，`Endpoint`就指代了我们现实生活中可以见到的那些外设，比如SSD, 显卡，网卡等。

整个 PCIe 网络呈现树形结构。其中，**Root Complex 是根节点，Switch 是中间节点，而 Endpoint 是叶子节点**。

另外，PCIe 中的上下游是相对于 Root Complex 而言的：靠近 Root Complex 的方向称为上游（Upstream），远离 Root Complex 的方向称为下游（Downstream）。这仅仅描述拓扑方向，不意味着数据只能单向流动。

现在，我们先对这张图有一个概念，之后，我们就会来初步解释一下当中涉及到的名词都是什么含义。

## Root Complex

**Root Complex（RC，根复合体）是主机系统与 PCIe 网络之间的连接入口。**

在典型的 SoC 中，CPU、内存控制器和各种硬件模块通过内部总线互联进行通信，而 PCIe 设备则使用 PCIe 协议进行通信。Root Complex 的职责，就是在这两个体系之间建立联系，使主机能够访问 PCIe 设备，同时也允许 PCIe 设备通过它访问主机系统中的资源。

需要明确的是，Root Complex 并非一个纯粹的软件抽象，而是具有真实硬件实现的功能模块。它通常集成在 CPU、SoC 或芯片组内部，并不一定是一颗独立的芯片。

另外，**一个系统中可以存在多个 Root Complex，而一个 Root Complex 也可以拥有多个 Root Port**。因此，Root Complex 和 Root Port 不是一一对应的关系。

从操作系统的角度来看，Root Complex 是 PCIe 设备发现和管理的起点。由于它本身位于 PCIe 网络的入口，操作系统通常通过 ACPI 或 Device Tree 等平台描述机制获取 PCIe Host Controller 的信息，进而开始枚举下游 PCIe 设备。

## Root Port

**Root Port（根端口）是 Root Complex 向下连接 PCIe 网络的端口。**

每个 Root Port 可以通过一条 PCIe Link 连接一个直接下游节点。这个节点可以是 Endpoint，也可以是 Switch。Root Port 不只是一个物理连接接口，还承担着桥接和事务转发的职责，使主机侧的请求能够进入对应的 PCIe 下游分支。我们可以将 Root Complex 理解为整个 PCIe 主机接口子系统，而 Root Port 则是这个子系统对外提供的具体连接端口。

需要注意，**Root Port 不需要掌握整个下游网络中每个设备的完整信息**。PCIe 采用分层组织的方式，各级桥接设备共同承担路由和转发职责。

## PCIe Switch

**PCIe Switch（交换设备）用于扩展 PCIe 网络，使一条上游 PCIe 连接能够进一步连接多个下游设备。** 它的定位与以太网交换机有些相似，但遵循的是 PCIe 自身的协议和转发规则。

一个典型的 PCIe Switch 包含：
- **Upstream Port（上游端口）**：朝向 Root Complex，连接上一级 PCIe 节点。
- **Downstream Port（下游端口）**：朝向 Endpoint 或其他 Switch，连接下一级 PCIe 节点。
- 
Switch 的主要职责是根据 PCIe 的路由机制，将事务转发到正确的端口。它并不是简单地把一条物理链路拆分成多条链路，而是作为一个实际的交换节点，连接多个独立的 PCIe Link。Switch 还可以级联，也就是一个 Switch 的下游继续连接另一个 Switch，从而形成层次更深的 PCIe 网络。在软件视角下，Switch 并不是一个完全不透明的节点。它的各个端口通常表现为 PCI Bridge Function，操作系统可以识别这些桥接结构，并继续发现后面的设备。

## Endpoint

**Endpoint（端点设备）是 PCIe 网络中的终端节点，负责提供实际的设备功能。** 常见的 Endpoint 包括 GPU、以太网控制器、NVMe SSD 控制器等。

与 Switch 不同，Endpoint 一般不负责继续扩展 PCIe 网络，而是通过 PCIe 接口向主机提供自身的硬件能力。例如：
- GPU 通过 PCIe 与 CPU 交换命令和数据。
- NVMe SSD 控制器通过 PCIe 接收存储操作请求。
- 网卡通过 PCIe 与主机内存交换网络数据。

需要注意，PCIe 设备并不只能被 CPU 被动访问。Endpoint 也可以主动发起 PCIe 事务，例如网卡通过 DMA 读写主机内存。因此，**PCIe 是双向的事务互联网络，而不是一条只能由 CPU 发起访问的外设控制总线**。

## PCIe Link

前面多次提到了 Link，这里简单解释一下。**PCIe Link（链路）是两个相邻 PCIe 端口之间建立的点对点通信连接。** 一条 Link 可以由一条或多条 Lane 组成，每条 Lane 提供双向的数据传输能力。

我们经常见到的 PCIe x1、x4、x8、x16，就是在描述 Link 所使用的 Lane 数量。
从拓扑角度看，只需要理解两个特点：
1. 每条 Link 连接两个相邻的 PCIe 端口。
2. 不同 Link 相互独立，设备之间的通信可以经过多个 Switch 和 Link。
这也是 PCIe 与传统 PCI 共享总线架构之间的重要区别。

## PCIe Function

最后，再引入一个与 Endpoint 密切相关的概念：**Function（功能）**。
前面讨论的 Root Complex、Root Port、Switch、Endpoint，主要描述 PCIe 网络的拓扑结构。而 Function 则属于另一层抽象，它描述的是 PCIe 设备向软件暴露的逻辑功能单元。

**Function 是 PCIe 中可以独立枚举、独立配置的基本逻辑单元。** 例如，一张物理 PCIe 设备可以同时提供多个逻辑功能：

```text
             PCIe Endpoint
                  |
          +-------+-------+
          |               |
      Function 0      Function 1
          |               |
     以太网控制器      管理控制器
```

这些 Function 可以共享同一套物理硬件和 PCIe Link，但每个 Function 都拥有独立的 PCIe Configuration Space，操作系统可以将它们识别为不同的 PCI 功能，并分别进行配置和驱动匹配。

另外，Function 并非 Endpoint 所独有。Root Port、Switch Port 等桥接节点，通常也会以 PCI Bridge Function 的形式暴露给操作系统。

因此，我们应当区分：
- **Endpoint、Switch、Root Port**：描述节点在 PCIe 拓扑中的角色。
- **Function**：描述 PCIe 系统中可被独立识别和配置的逻辑功能。

这一抽象非常重要，因为后续讨论 PCIe Configuration Space、设备枚举和驱动模型时，我们实际操作的基本对象往往就是 Function。

从操作系统的视角来看，**Function 是 PCIe 设备枚举、配置和驱动匹配的基本单元**。例如，在 Linux 中，每个被枚举到的 PCI Function 都会对应一个独立的 `struct pci_dev`，拥有自己的 Configuration Space，并且可以分别绑定不同的驱动程序。

因此，我们可以将 Function 理解为 **PCIe 向操作系统暴露的基本逻辑设备单元**。不过，需要区分逻辑管理单元与数据访问粒度：Function 并不像内存中的字节那样代表最小的数据访问单位。操作系统在识别和管理 Function 之后，仍然需要访问其配置空间或 MMIO 空间中的具体寄存器。

换句话说，**Function 回答的是“操作系统正在管理哪个逻辑设备”，而具体的寄存器访问回答的是“操作系统正在操作这个设备的什么内容”。**

## 小结

至此，我们可以从两个视角理解 PCIe 系统。
**从硬件互联的视角来看**，PCIe 是一个以 Root Complex 为根、以 Switch 为中间节点、以 Endpoint 为终端节点的树形互联网络。Root Port 负责连接下游分支，各个节点通过独立的 PCIe Link 进行通信。
**从操作系统的视角来看**，PCIe 提供了一套标准化的设备发现、配置和管理机制。操作系统可以从 PCIe Host Bridge 开始，逐层发现下游拓扑，并识别其中的 Function，而无须预先了解每一个设备的具体硬件实现。
更进一步，我们可以将 PCIe 系统中的职责分为两部分：
- **操作系统负责建立和管理 PCIe 网络的软件视图**，包括设备发现、资源分配和驱动管理。
- **Root Complex、Root Port、Switch 等硬件负责实际的事务传输和转发**，使主机与 Endpoint 能够通信。
