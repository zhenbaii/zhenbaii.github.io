根据架构，抽象层级的不同，虚拟机可以被分为很多类型。

### 进程虚拟机

所谓的进程虚拟机，就是针对进程运行环境的抽象。换句话说，他并不会去真的仿真CPU，内存等系统级别的资源，而只在进程层面上进行虚拟化。通俗的说，进程虚拟机是把一套"抽象计算机/运行时环境(Runtime software)"塞进宿主操作系统的一个普通进程里，只服务一个应用程序。宿主OS看到的只是一个普通进程，比如`java`进程，但是这个进程却支撑着其他进程的运行。

到这里，进程虚拟机在我们看来，就是宿主机中的一个普通进程，其支撑着上层应用的运行，看起来像是一个普通的后台进程而已。但是，我们为什么还把他称作虚拟机呢？一定是因为他和架构联系起来了。当我们谈论机器时，一定会谈论到它的架构，进程虚拟机也不例外。

#### vISA(virtual ISA)——虚拟指令集架构
进程虚拟机之所以叫做虚拟机，就是因为它定义了一套所谓的虚拟指令集架构。为什么叫做虚拟？因为这个架构不像ARM，x-86, RISCV一样存在真实的硬件平台，而是专门服务于进程虚拟机这一台虚拟机器的专用架构。运行在这台虚拟机器上的进程，则需要面向这个架构去编程。我们可以举几个现实中存在的例子：
-  JVM的vISA是Java字节码
-  .NET的vISA是CIL
-  CPython的vISA是CPython字节码
-  Lua VM的vISA是Lua bytecode
- ....
许多脚本语言的运行时本质上就是一个进程虚拟机。

vISA规定了：
-  支持的指令，操作数的编码方式
-  数据类型
-  内存模型
-  方法调用，异常

面向进程虚拟机的程序，只要把源码编译为对应的vISA机器码(比如Java字节码)，就不用再关心底下的真实硬件平台是x86还是ARM，进程虚拟机会负责对真实硬件平台的适配。

#### 进程虚拟机的核心能力——跨平台
这是进程虚拟机的一个十分核心且重要的能力。运行在虚拟机上的程序，只需要面向虚拟机的vISA编译后，就不用再重新编译一次，可以在所有真实的硬件平台上运行，只要虚拟机支持了对应的硬件平台。现在，分发变成了面向虚拟机的vISA的二进制分发，而不是直接面对目标平台分发。实际工作从移植应用到移植虚拟机，哪边成本低可想而知。下图就很好地展示了这个关系：
```
源代码 → 编译器 → vISA 字节码（平台无关）
                        ↓
        ┌───────────────┼───────────────┐
     JVM@x86        JVM@ARM         JVM@RISC-V
        ↓               ↓               ↓
     x86 机器码     ARM 机器码     RISC-V 机器码
```

#### 进程虚拟机的核心能力——安全
因为程序面向的是一套由虚拟机定义、被虚拟机控制的指令集，虚拟机可以在执行前和执行中做很多CPU运行时做不到的事情：
-  字节码验证
-  受控的内存模型
-  沙箱和权限限制

和真实设备做对应：

| 真实机器/系统虚拟机 | 进程虚拟机                     |
| ---------- | ------------------------- |
| CPU + 指令集  | 执行引擎（解释器/JIT）+ vISA 字节码   |
| 内存 + MMU   | 虚拟机管理的堆/栈/GC              |
| 系统调用接口     | 运行时库 + 本地接口（JNI/P-Invoke） |
| 特权级/保护环    | 字节码验证器 + 安全管理器            |
| 设备         | 通过宿主 OS 代理的文件/网络/线程       |

### 系统虚拟机

和进程虚拟机做出最大区分的就是，系统虚拟机向软件呈现的是一台完整的、真实存在的计算机：
-  真实的CPU架构，如x86, ARM
-  物理内存
-  中断控制器，时钟，总线
-  磁盘，网卡，显卡，USB
-  启动固件
-  ...
具体来说，一般需要提供CPU虚拟化，I/O虚拟化，内存虚拟化等全栈的虚拟化方案。

根据对硬件的掌控程度不同，系统虚拟机也可以分为本地虚拟机和宿主虚拟机。

#### 本地虚拟机
所谓的本地虚拟机，就是直接掌控硬件资源的一类虚拟机。这类虚拟机运行在最高的特权级下，直接掌控所有硬件资源。这类虚拟机一般也叫做裸金属虚拟机/裸金属Hypervisor.  
这类虚拟机的优点是最高效，因为直接掌控了硬件资源，没有任何中间层开销; 但是缺点也很明显，就是需要自己编写所有复杂的硬件驱动。计算机行业发展到今天，外设类型和型号越来越多，这些硬件驱动都是优先适配那些主流的操作系统，比如Linux和Windows. 对于本地虚拟机来说，由于自己就掌控硬件资源，自然地，他就无法复用这些已有的面向特定操作系统的驱动实现，而需要自己从头实现这些驱动。

总的来说，我们可以把本地虚拟机理解为一种特殊的裸机软件。 典型的代表有VMware ESXi, Xen. 

#### 宿主虚拟机
这类虚拟机以来一个host OS， 在host OS上搭载一个虚拟机。其必须通过宿主OS作为媒介，来访问真实的物理硬件。这类虚拟机由于host OS这个中间层的存在，性能会稍微损失一些。但是优点是可以利用host OS丰富的硬件生态，比如可以直接复用Linux的丰富硬件驱动实现。

根据host和guest架构的异同，所需要的技术也是不同的。如果是同架构，并且物理硬件支持虚拟化扩展，那么guest的大多数指令的运行速度几乎是原生的，除了那些特权级指令，以及I/O场景。如果是不同架构，就需要用动态二进制翻译等技术了。
