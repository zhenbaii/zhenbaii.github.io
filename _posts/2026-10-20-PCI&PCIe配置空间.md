前面，我们已经对PCI&PCIe中的硬件拓扑和逻辑拓扑有了更好的理解，知道了操作系统配置和操作的基本单位是Function。 下一步，我们就来具体讲一讲配置空间的具体构成。

我们知道，PCI和PCIe在软件层面是可以做到兼容的，或者说是向下兼容。那么，他们的配置空间也必然是有重叠的地方的。我们仍然首先去回顾一下PCI的配置空间，然后再讲解PCIe的配置空间。下图简单展示了这两者的区别和共同点所在：
```
						PCI                     PCIe
				   Configuration             Configuration
					  Space                     Space
			
			0x000  +-------------+       +-----------------+  0x000
				   |             |       |                 |
				   | PCI Header  |       |   PCI Header    |
				   |  64 Bytes   |       |    64 Bytes     |
			0x040  +-------------+       +-----------------+  0x040
				   |             |       |                 |
				   | Capabilities|       |  Capabilities   |
				   |             |       |                 |
			0x100  +-------------+       +-----------------+  0x100
										 |                 |
										 |   PCIe Extended |
										 |  Configuration  |
										 |      Space      |
										 |                 |
			0x1000                       +-----------------+  0x1000
```

下面我们分模块来讲解每一部分都去配置什么功能。

## PCI & PCIe —— PCI Header

如上图所示，这部分是两者共享的。这部分用于描述Function的基本信息和配置资源，占据Configuation Space的前64个字节。这部分主要是回答以下问题：
- 我是谁？ 厂商、设备型号、设备类别等。
- 我是什么类型的 Function？ 普通设备功能还是 Bridge？
- 我需要什么资源？ 例如 MMIO 地址空间。
- 操作系统如何控制我？ 例如是否允许发起 DMA。
- 我还支持哪些能力？ 提供查找 Capability 的入口。

下图展示了PCI Header的结构：
```
					Offset
					0x00  +---------------------------+
					      | Vendor ID / Device ID     |
					0x04  +---------------------------+
					      | Command / Status          |
					0x08  +---------------------------+
					      | Revision ID / Class Code  |
					0x0C  +---------------------------+
					      |  Cache Line Size /        |
					      |  Latency Timer   /        |
					      |  Header Type / BIST       |   
					0x10  +---------------------------+
					      |                           |
					      | Type-specific Registers   |
					      |                           |
					      | Type 0 / Type 1 / Type 2  |
					      |                           |
					0x40  +---------------------------+
```

可以看到，总体上是分为两个部分， 一部分无论Type和PCI/PCIe都一样的字段，一部分则根据Type的不同而不同。

### Shared part

对于公共部分，其各个字段的定义和作用如下表所示：

| Offset      | 字段              | 大小  | 作用              |
| ----------- | --------------- | --- | --------------- |
| `0x00`      | Vendor ID       | 2 B | 厂商标识            |
| `0x02`      | Device ID       | 2 B | 设备型号            |
| `0x04`      | Command         | 2 B | 基本控制            |
| `0x06`      | Status          | 2 B | 状态信息            |
| `0x08`      | Revision ID     | 1 B | 设备版本            |
| `0x09–0x0B` | Class Code      | 3 B | 设备类别和编程接口       |
| `0x0C`      | Cache Line Size | 1 B | 缓存行大小相关字段       |
| `0x0D`      | Latency Timer   | 1 B | 传统 PCI 延迟计时相关字段 |
| `0x0E`      | Header Type     | 1 B | 决定后续布局，并标记多功能属性 |
| `0x0F`      | BIST            | 1 B | 内建自检            |
虽然这部分是公共的，但是在PCIe中，实际上某些字段已经不再使用，只是为了保持兼容而留了下来。

### Type-specific part

Type表示的是Function Type, 在PCI时代，就已经定义了如下三种Type：

|Type|名称|适用对象|
|---|---|---|
|Type 0|Normal Device Header|普通 PCI Function|
|Type 1|PCI-to-PCI Bridge Header|桥接 Function|
|Type 2|CardBus Bridge Header|传统 CardBus Bridge|

而在PCIe时代，只沿用了Type 0和Type 1, Type 2一般已经不用。下表就展示了这三个Type在PCI和PCIe的硬件拓扑和逻辑拓扑中，分别指代了哪个主体：

|Header Type|传统 PCI 中对应的主体|PCIe 中对应的主体|逻辑角色|
|---|---|---|---|
|Type 0|普通 PCI 设备中的 Function，例如网卡、声卡|普通 Endpoint Function，例如 GPU、NVMe 控制器|提供设备功能|
|Type 1|PCI-to-PCI Bridge|Root Port、Switch Upstream Port、Switch Downstream Port|连接不同的逻辑 Bus|
|Type 2|PCI-to-CardBus Bridge|原生 PCIe 拓扑中通常不使用|连接 PCI 与 CardBus|
