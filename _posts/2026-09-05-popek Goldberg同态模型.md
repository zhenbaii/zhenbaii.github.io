这是虚拟化领域十分著名的一篇论文。其建立了一个形式化的机器模型和虚拟机模型。假设我们有一台真实的机器$Hardware$, 正常情况下，操作系统直接运行在真实硬件上：
$$
Application \to OS \to Hardware
$$
在虚拟化场景下，多了一层$VMM$做代理：
$$
Guest\, Application \to Guest \, OS \to VMM \to Hardware
$$
同态模型对$VMM$提出了以下三个要求：
- **Equivalence（等价性 / Fidelity）**  
    一个程序在虚拟机里运行时，其行为应该与它直接运行在等价真实机器上基本一致。
- **Resource Control（资源控制）**  
    VMM 必须最终掌控所有硬件资源。Guest OS 不能绕过 VMM 随便操作真正的 CPU、内存、设备等。
- **Efficiency（效率）**  
    绝大多数普通指令应该可以直接在真实 CPU 上执行，而不是每条指令都交给 VMM 模拟。

上面这个比较好理解，真正重要的是他针对ISA的指令所提出的要求。一个ISA是否满足这个要求，直接决定了它可不可以通过这个同态模型构建一个$VMM$层。

这篇论文中，ISA的指令被分为了两类，即所谓的特权级指令和敏感指令。需要注意的是，他们两者不是互斥的，而是彼此之间都包括的。

### 特权指令

这类指令在低特权级执行时会产生trap, 而在高特权级执行时可以正常执行。这类指令对于VMM来说是十分自然的，因为在trap的途中就可以对指令进行截获，模拟和返回：
```
Guest OS:
    修改某个系统控制寄存器
            ↓
    CPU发现当前不是最高权限
            ↓
           trap
            ↓
           VMM
```

### 敏感指令

敏感指令，就是泛指那些会影响系统状态，或者暴露系统状态的指令。对于一些指令来说，它既是特权指令，也是敏感指令，比如页表的切换指令; 有一些指令，虽然是敏感指令，但是却不是特权级指令，它允许直接在用户态执行，而不会产生trap. 后者现在已经很少了，因为很多架构为了支持虚拟化，把这些坑都补上了。不过在早期的架构，这些指令却是非常常见的。我们以早期的x86为例子讲一讲这些指令，以及这些指令对于虚拟化所产生的阻碍。

x86有一个`IF`寄存器，即Interrupt Flag，其取值和含义如下：
```
IF = 1   接受可屏蔽中断
IF = 0   屏蔽可屏蔽中断
```

在早期的x86架构下，这个位是不允许用户态修改的，因为是敏感指令。但是，在不允许修改的同时，它并不会显式地产生trap陷入内核态，告知内核用户态执行了一条非法指令，而是静默忽略。因此，它就是十分典型的敏感且非特权级指令。这放在虚拟化场景下，就会出现一个很大的问题：
```
Guest OS 认为自己是内核态
        ↓
POPF，试图把 IF 改成 0
        ↓
实际上 Guest 被 VMM 放在低特权级
        ↓
CPU 不允许它修改 IF
        ↓
IF 保持不变
        ↓
但旧 x86 又不一定因此产生 trap
		↓
而且Guest OS以为自己修改成功了
```

Guest可能以为自己已经关中断了，但实际上还是开着的！

因此，同态模型要求把敏感指令都纳入到特权级指令的框架下，这样子，系统状态的变更(以及针对系统状态变更的任何尝试)都会被$VMM$截获。这样子的框架下的虚拟机实现，其实就是所谓的
$$
Trap-and-Emulate
$$
我们说，满足这个条件的ISA天然适合经典的虚拟化。但是不是说不满足这个条件的，就无法完成虚拟化。比如，我们还可以通过如下方式完成：
-  二进制翻译
-  软件模拟
-  硬件虚拟化扩展
