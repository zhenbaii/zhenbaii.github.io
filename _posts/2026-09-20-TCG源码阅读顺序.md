按 **TB 的一生** 读，不要按目录、也不要按文件大小。每一段只回答一个问题，过关再往下。前后端只当标本，不当主课。

总顺序：

**先知道产品是什么 → 再看它怎么被用 → 再看它怎么被造 → 最后才进 `tcg.c` 和 host 后端。**

源码根目录默认是 `qemu-camp-2026-k230/`。

```text
TB 是什么
  → 主循环怎么用 TB
    → tb_gen_code 外壳
      → translator_loop 怎么切 TB、填 IR
        → 一条 addi 标本冒出 tcg_gen_*
          → IR / 优化 / tcg_gen_code 骨架
            → 执行 + chaining
              → helper / unwind / 失效
                → qemu_ld + TLB 机制
                  → tcg.c 寄存器分配
                    → 需要时才看 host 后端
```

TCG 自己的链是 **1 → 4 → 6 → 7 → 9 → 13**。第 5、14 步只为让链条可见。

---

## 0. 先读官方概念，不读实现

`docs/devel/tcg.rst` 里这四节就够（标题与行号按这一棵树）：

| 要建立的概念 | 文中标题 | 行号 |
| --- | --- | --- |
| TB 里缓存了哪些 CPU 状态 | CPU state optimisations | 19–31 |
| TB 之间如何直接串起来 | Direct block chaining | 33–125 |
| 代码被改了为什么旧 TB 不能再用 | Self-modifying code and translated code invalidation | 127–149 |
| 软件 MMU / TLB 在做什么 | MMU emulation | 170–191 |

开头 1–17 行扫一眼。先不看 **Exception support**（152–168）和 **Profiling JITted code**（193–216）。`docs/devel/tcg-ops.rst` 等真正看见 `TCGOp` 再查。

过关标准：能用自己的话说明「翻译单位是 TB，不是一条指令，也不是整段 trace」。

---

## 1. 产品长什么样

- `include/exec/translation-block.h`：`pc`、`flags`、`cflags`、`tc.ptr`、jmp slot
- `include/accel/tcg/tb-cpu-state.h`：查找键
- `include/accel/tcg/cpu-ops.h`：加速器向 guest 要的钩子。这时只看名字：`translate_code`、`get_tb_cpu_state`、`tlb_fill`

过关标准：命中一次 TB 需要哪些键；生成结果是一块可执行的 host 代码。

---

## 2. 使用侧：主循环只做三件事

`accel/tcg/cpu-exec.c` 的 `cpu_exec_loop` → `tb_lookup` →（miss）生成 /（hit）`cpu_tb_exec`。

过关标准：能画出 `查 TB → 没有就译 → 有就跑`。exception / interrupt / icount 先跳过。

这一步解决「为什么会翻译」。没有它，后面的 `tb_gen_code` 会显得没来由。

---

## 3. 生产侧外壳

`accel/tcg/translate-all.c` 的 `tb_gen_code`。

只跟两条调用：

1. `tcg_ops->translate_code(...)` → 往 `TCGContext` 里塞 IR
2. `tcg_gen_code(...)` → IR 变成 `tb->tc.ptr`

过关标准：分清「前端填链表」和「编译器吐机器码」是两步，不是一步。

---

## 4. 填 IR 的通用循环（仍无 ISA）

`accel/tcg/translator.c` 的 `translator_loop`，对照 `include/exec/translator.h` 的 `TranslatorOps`。

看循环怎么停：`DISAS_NEXT` / `TOO_MANY` / `NORETURN`，以及 `max_insns`、页边界。这就是 TB 的切法。

过关标准：不看任何 `trans_addi`，也能说出一个 TB 何时结束。

---

## 5. 标本：一条指令如何冒出 IR

打开即可，不要读完整前端：

- `target/riscv/translate.c` 里 `riscv_translate_code`、`riscv_tr_translate_insn`、`decode_opc`
- `insn_trans/trans_rvi.c.inc` 里 **只看一条** `trans_addi`（之后再加一条 `trans_lw`）

过关标准：看见 `tcg_gen_*` 被调用。RISC-V 编码、CSR、扩展全部放下。

同时跑 `-d in_asm,op`，把日志和这条 `trans_*` 对上。

---

## 6. IR 本身

- `include/tcg/tcg-opc.h`：opcode 表
- `include/tcg/tcg.h`：`TCGContext`、临时变量
- `include/tcg/tcg-op.h` / `tcg-op-common.h`
- `tcg/tcg-op.c`：`tcg_gen_add_*` 如何 `tcg_emit_op`

过关标准：`-d op` 里每一行能指到一种 opcode；知道 temp / constant / global（映射到 `CPURISCVState` 字段）的差别。

到这里，TCG 作为「中间语言」才落地。

---

## 7. 编译流水线：先读骨架，不读寄存器分配

`tcg/tcg.c` 的 `tcg_gen_code()`，按函数调用往下，不要从头读 7000 行：

1. dump 原始 IR（`-d op`）
2. `tcg_optimize()` → `tcg/optimize.c`（先当黑盒：常量传播、死代码）
3. liveness
4. host `tcg_out_*`（先当接口）
5. 代码写进 `tcg/region.c` 的 buffer

过关标准：能把 `-d op` 和 `-d op_opt` 的差异说成「优化器改了链表」，而不是「后端改了」。

`optimize.c` 先读入口和几种典型规则，不必一次读完。

---

## 8. 跑起来

回到 `cpu-exec.c` 的 `cpu_tb_exec` → `tcg_qemu_tb_exec`。

弄清 prologue（进 TB 前怎么把 `env` 放到 host 约定里）和 epilogue（为什么会回到主循环）。实现仍在 host 后端里，这一步只认接口。

过关标准：host 代码不是 `main()` 调的，是 JIT 出来后被间接跳进去的。

---

## 9. chaining：主循环的加速器

对照 `docs/devel/tcg.rst` 的 Direct block chaining，读：

- `tcg_gen_goto_tb` / `tcg_gen_exit_tb`（`tcg/tcg-op.c`）
- `tb_add_jump` / `tb_set_jmp_target`（`accel/tcg/cpu-exec.c`）
- `helper_lookup_tb_ptr`（同文件；对应 `lookup_and_goto_ptr`）

标本可看 `target/riscv/translate.c` 里的 `gen_goto_tb`，只看控制流，不看 RISC-V。

过关标准：能区分「回主循环再 `tb_lookup`」和「TB 结尾直接跳下一块」。

---

## 10. helper 与异常回退

- 通用：`accel/tcg/tcg-runtime.c`（尤其 `lookup_tb_ptr`）
- 约定：`include/exec/helper-*.h` 的宏在干什么（`DEF_HELPER` → `gen_helper_*` / `helper_*`）
- `translate-all.c` 的 `cpu_restore_state`：host PC 如何回到 guest PC（`insn_start` 记录的位置）

过关标准：知道哪些语义不做成 TCG op，而是 `call` 进 C；异常时靠 TB 里的 insn 边界信息 unwind。

guest 的 `helper_raise_exception` 实现可以不读。这时可以回头补 `tcg.rst` 的 Exception support。

---

## 11. TB 为何会作废

`accel/tcg/tb-maint.c`：插入、按物理页失效、`tb_flush`。

结合文档里的 Self-modifying code。过关标准：页表变了、代码被写了，为什么不能继续跑旧 TB。

---

## 12. 访存：先 IR，再 TLB 机制

有了 `lw` 标本再来：

- `tcg/tcg-op-ldst.c`：`qemu_ld/st` 这种 IR
- `accel/tcg/cputlb.c`：快路径 / miss

`target/riscv/cpu_helper.c` 的 `tlb_fill` 是 RISC-V 走页表，点到「miss 时回调这里」即可。

过关标准：能分开「翻译期发出 qemu_ld」和「执行期走软件 TLB」。不要一上来把 `cputlb.c` 当翻译器读。

---

## 13. 最后才深挖编译器内核

这时再精读 `tcg.c`：临时变量生命周期、liveness、寄存器分配、helper 的调用约定。这是核心里最硬的一块。

---

## 14. 需要时才打开 host 后端

`tcg/<你的host>/tcg-target.c.inc` 放在最后：只跟一条已经在 `-d out_asm` 里见过的 op（比如 `add`）。指令选择是 host ISA，不是 TCG 课。

`tests/tcg/` 忽略，直到要写 guest 测试。`tcg/tci/` 忽略，除非 host 没有 native 后端。

---

## 每一段怎么停

能讲清这个环节的**输入和输出**，再打开下一份文件。不要在 `translator_loop` 还没闭环时钻进 `tcg.c`。
