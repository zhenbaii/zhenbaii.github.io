在上一篇文章中，我们从系统架构的角度出发，认识了 PCIe 网络中的几个核心组成部分：Root Complex、Root Port、Switch、Endpoint 以及 Function，并初步建立了 PCIe 树形互联结构的心智模型。

然而，**物理拓扑并不等同于操作系统所看到的逻辑拓扑**。对于操作系统而言，仅仅知道设备之间如何连接是不够的，还需要一套统一的抽象和寻址机制，使其能够识别和定位 PCIe 网络中的每一个 Function。

为此，PCIe 继承了传统 PCI 的逻辑总线模型，通过 **Bus、Device、Function（BDF）** 对设备进行组织和编号，并借助 **Bridge** 将不同的逻辑 Bus 连接起来，从而将复杂的物理互联结构抽象为一套层次清晰、可统一管理的逻辑拓扑。

这一节，我们仍然不急于深入具体的寄存器和协议细节，而是围绕 **Bus、Bridge、Device、Function** 这几个核心概念展开，理解它们各自的含义及相互关系，并最终回答一个问题：**操作系统如何在庞大的 PCIe 网络中唯一标识一个 Function？**

## PCI总线模型——历史回顾

在进入PCIe总线的讲解之前，我们有必要简单回顾一下PCI总线接口模型。从PCI到PCIe, 整个硬件拓扑和电气接口都是不兼容的，但是，驱动硬件的软件模型却是兼容的，因此，我们在这一小节对PCI做一个简单的回顾，以及把两者做一个简单的对比。

PCI（Peripheral Component Interconnect）是 20 世纪 90 年代出现的计算机外设互联标准。传统 PCI 采用共享式并行总线，多个设备连接在同一条总线上。我们可以用下图表示PCI的硬件拓扑：
```
                    CPU / Memory
                         |
                    Host Bridge
                         |
                         |
  =================== PCI Bus 0 ===================
       |                 |                |
       |                 |                |
    PCI 网卡          PCI 声卡       PCI-to-PCI Bridge
                                           |
                                           |
                      ================ PCI Bus 1 ================
                           |                        |
                        PCI 网卡                存储控制器
```

可以看到，在PCI中，设备是并联在同一条PCI Bus上的，并且，这里的设备可以是真正的Endpoint，也可以是一个`PCI-to-PCI Bridge`桥接层，这个桥接层底下会接入另一条PCI Bus。 因此，传统的PCI实际上也是支持多层结构的。之所以要支持这种层级，一方面是方便更细颗粒度的管理，另一方面也是因为一条PCI Bus支持接入的设备数量是有限的。当外设数量太多时，就只能采用这种多层级的结构。

在上述的硬件拓扑图中，有三个基本角色：
- Host Bridge：连接 CPU/内存系统与 PCI 总线。
- PCI Bus：设备共享的通信通道。
- PCI Device：连接在总线上的设备，比如网卡、声卡、 PCI-to-PCI Bridge。

在一条PCI Bus上，可以接入多个设备，为了在软件中区分它们，PCI为每个Device都分配了一个编号。但是，一个PCI Device可能还可以提供多种不同的功能。比如，一张集成式的PCI扩展卡可能同时集成了网络和音频的功能。为了进一步区分不同的功能模块，提供更细颗粒度的管理，PCI进一步区分了同一个Device的不同Function：
```
PCI Bus 0
   |
   +-- Device 0
   |      |
   |      +-- Function 0：网络控制器
   |      +-- Function 1：音频控制器
   |
   +-- Device 1
          |
          +-- Function 0：存储控制器
```

到这里，我们其实已经完整建立了`Bus -> Device -> Function`的三级层次。通过这个三元组，我们就可以唯一定位一个Function, 而Funciton正是操作系统管理PCI和PCIe设备的基本单元。

到这里，这些概念其实早在PCI时代就已经有了，PCIe沿用了这些称呼，但是其硬件拓扑和电气设计和PCI是完全不同的，只是在软件层面上是兼容的。

## PCI和PCIe的区别

PCIe的推出，并不是为了要完全取代PCI，而是为了解决PCI中存在的某些问题，特别是传输速率的问题。PCIe相比PCI，在很大程度上保留 PCI 软件模型的前提下，重新设计了底层互联架构。下图是两者的硬件拓扑图：
```
                传统 PCI：共享总线
                  CPU / Memory
                       |
                  Host Bridge
                       |
  ================== PCI Bus ==================
       |                 |               |
       |                 |               |
    Device 0          Device 1        Device 2
     (NIC)             (GPU)           (SSD)

				
				 PCIe：点对点互联
                  CPU / Memory
                       |
                  Root Complex
                       |
                 +-----+-----+
                 |           |
             Root Port   Root Port
                 |           |
             PCIe Switch    GPU
                 |        (Endpoint)
            +----+----+
            |         |
           NIC       SSD
       (Endpoint) (Endpoint)
```

传统的PCI采用并联的共享总线，多个设备连接到同一组地址，数据和控制信号线上，通常来说，来进行传输时，需要和i2c等总线协议一样进行总线仲裁并独占总线，因此其整体的传输速率，就收到了PCI Bus的制约。而PCIe则采用了点对点互联的架构，Port之间可以建立单独的高速总线连接，独享总线带宽，因此其速率相比上一代PCI技术得到了大大的提升。

其他差别还包括软件层面的实现差别， 电气接口的不同，配置空间的不同等等，这里就不在这里过多展开。我们要认识到的最重要的区别就是，两者在软件层面基本兼容，但是其底层的硬件拓扑和对应的电气接口是有很大的不同的。

## PCI和PCIe的软件接口继承

前面我们提到了，PCI相比PCIe主要发生在底层硬件拓扑和电气接口的改变，上层的软件接口，概念是没有太大的差异的。这主要是考虑了操作系统的兼容性问题，PCI接口推出许久，操作系统针对它的实现也已经积累了很多，固化下来，此时再考虑设计一套全新的接口用来适配PCIe，就会引入不必要的工作量，同时埋下兼容性等隐患。这一小节，我们就来详细讲解一下PCI中留下的软件概念，在PCIe中体现为什么东西，对比PCI和PCIe在这些概念上对应的底层拓扑。

### Bus
在PCI中，Bus真的就是一条物理上存在的Bus，是设备共享的物理通信通道。
```
                   Host Bridge
                        |
  =================== Bus 0 ===================
       |                |                |
    Device 0         Device 1      PCI-PCI Bridge
     (网卡)            (声卡)             |
                                          |
                               ========= Bus 1 =========
                                  |               |
                               Device 0        Device 1
                                (网卡)           (磁盘)
```

这里有几个特点：
- 一个 Bus 可以连接多个 Device。
- 同一 Bus 上的设备共享物理信号线和带宽。
- 不同 Bus 可以通过 PCI-to-PCI Bridge 连接起来。
- 每个 Bus 具有自己的编号，用于区分不同总线上的设备。

因此，传统 PCI 的 Bus 同时具有物理意义和逻辑意义：它既是实际的共享通信通道，又是操作系统组织设备的一个层次。

而在PCIe中，在物理层面上已经不存在一个所谓的共享Bus，但是它仍然沿用Bus的概念来管理设备。具体来说，在PCIe中，硬件拓扑上的每一个非叶子节点，都会对应一个Bus, 如下图所示：
```
Root Complex
    |
  Bus 00
    |
 Root Port（Bridge）
    |
  Bus 01
    |
 Switch Upstream Port（Bridge）
    |
  Bus 02（Switch 内部逻辑总线）
    |
    +-- Downstream Port A（Bridge）
    |       |
    |     Bus 03
    |       |
    |      SSD
    |
    +-- Downstream Port B（Bridge）
            |
          Bus 04
            |
           NIC
```

除了真正的Endpoint没有再往下发展，任何可以继续往下发展的，比如root port, downstream port, 都会对应一个逻辑的Bus.

### Bridge
Bridge, 全称是PCI-to-PCI Bridge, 是两条PCI Bus之间的桥梁，用于隔离两条不同总线之间的事务，并按照自己的规则传递两条总线之间的消息。在PCI中，这是一个真实存在的物理结构。而到了PCIe, 则和Bus一样，退化成了一个逻辑上的概念。在拓扑图中，连接两条逻辑Bus的那个实体就会变成一个逻辑的Bridge， 如下图所示：
```
                   Root Port
                       |
                    Bus 01
                       |
               Switch Upstream Port
                    (Bridge)
                       |
                    Bus 02
                (Switch 内部)
                       |
              +--------+--------+
              |                 |
        Downstream Port A   Downstream Port B
            (Bridge)           (Bridge)
              |                 |
            Bus 03            Bus 04
              |                 |
             SSD               NIC
```

### Device & Function
传统 PCI 的 Device 相对容易理解。一条Bus上可以连接多个设备，为了区分不同的设备，就给Bus上的设备分配了一个逻辑编号，这个编号就叫做Device。 而一个Device本身可能可以提供不同的功能，因此，Device内部再区分不同的功能编号，称为Function。 这些Funciton才作为操作系统配置的最小单位。
```
PCI Bus 00
    |
    +-- Device 00
    |      |
    |      +-- Function 0：网络控制器
    |      |
    |      +-- Function 1：存储控制器
    |
    +-- Device 01
           |
           +-- Function 0：声卡
```

在PCI中，每个 Bus 最多提供 32 个 Device 编号，每个 Device 最多包含 8 个 Function。 因此，才需要前面所提到的PCI-to-PCI Bridge来支持更多的设备接入。

在PCIe中，这两个概念也被保留下来，并且在含义上其实差距并不大。只不过，在PCIe中，Device现在不一定是我们所熟知的那些Endpoint, 如网卡，声卡，显卡，而是有可能是一个端口。端口本身作为Device和Function暴露给操作系统，使得操作系统可以配置他们。下图就很好展现了这个区别：
```
                  Root Complex
                       |
                    Bus 00
                       |
                Root Port 00:01.0
                       |
                   PCIe Link
                       |
                    Bus 01
                       |
                  PCIe Endpoint
                    （网卡）
                       |
                 Device 00
                  /       \
          Function 0    Function 1
```

我们要认识到的就是，Device就是接在Bus下的东西，无论这个Bus是PCI的物理实体Bus, 还是PCIe的逻辑Bus. 在PCI中，接在Bus下的就是Endpoint. 而在PCIe中，不仅是Endpoint, 还可能是root port, switch upstream port, switch downstream port. 
### BDF

BDF, 即Bus-Device-Function, 就是把前述概念结合起来，在一个PCI编码域中，唯一定位一个Function。 在PCI中，三个编号的范围和定义如下表所示：

| 字段 | 位宽 | 编号范围 | 作用 |
|---|---|---|---|
| Bus | 8 bits | 0–255 | 标识逻辑总线 |
| Device | 5 bits | 0–31 | 标识 Bus 上的 Device 编号 |
| Function | 3 bits | 0–7 | 标识 Device 下的 Function |

通过这三个编号，就可以在某个PCI编码域内唯一定位一个Function. Linux中，格式如下：
```
         Bus : Device . Function
          03 :   00   .    1
```
